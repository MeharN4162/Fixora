Invisible Character Generator

Generate real zero-width and blank Unicode characters — with a visual preview so you can see exactly what you're copying, since you can't see it in a plain text field.

How to Generate Invisible Characters

  1. Choose which invisible character you want from the dropdown (Zero Width Space, ZWNJ, ZWJ, Word Joiner, Zero Width No-Break Space/BOM, Non-Breaking Space, Hangul Filler, or Braille Pattern Blank).
  2. Read the description below the dropdown to see what that character actually does and where it's commonly used or misused.
  3. Set how many copies you need with the Repeat Count field (1–500) — higher counts are useful for padding.
  4. The output field updates instantly with your generated string.
  5. Check the Visual Preview to confirm exactly what you're about to copy, since the character itself is invisible or blank.
  6. Click "Copy" to copy it to your clipboard.
  7. Paste it wherever you need blank-looking space.

Frequently Asked Questions

Will these invisible characters bypass a website's character limit?

No — don't count on that. Zero-width and blank characters still count as characters toward almost every platform's length limit; they just don't display visible ink. This tool is for cases where you want blank-looking space, not for stretching character limits.

Will every platform accept zero-width characters?

Not always. Many chat apps, usernames, and form fields strip zero-width characters automatically, and some validators reject them outright as suspicious or invalid input. Test on the specific platform you're targeting before relying on it.

What's the difference between the zero-width options and Hangul Filler or Braille Pattern Blank?

Zero Width Space, Zero Width Non-Joiner, Zero Width Joiner, and Word Joiner are true zero-width characters — they take up no visible width at all. Hangul Filler and Braille Pattern Blank instead render as a small blank-looking glyph with actual width, which is why they're often used for things like a 'blank' username where a field requires at least one visibly-occupied character.

Why would I want an invisible character at all?

Common uses include blank social media display names, spacing out text in places that strip leading or trailing whitespace, or working around form fields that reject a completely empty value.

Is this guaranteed to work for blank usernames on every app?

No guarantee — platforms change their filtering rules over time, and what works today may be blocked tomorrow. Treat this as a starting point to experiment with, not a guaranteed trick.

Why does the tool show a "Visual Preview" with labels like ZWSP instead of just the character?

Because these characters render as literally nothing (or as a blank-looking glyph) in a plain text field, you can't otherwise confirm what you copied. The Visual Preview wraps each character in a labeled box (like ZWSP or NBSP) purely for your own screen — that label is never part of the text you actually copy or paste.

What's the difference between Word Joiner, the BOM character, and Non-Breaking Space?

Word Joiner (U+2060) is a modern, purely zero-width character with no line-break point. Zero Width No-Break Space (U+FEFF) does the same job but doubles as the Byte Order Mark when it appears at the very start of a file, which can confuse some parsers if it shows up mid-text — Word Joiner is the safer modern choice. Non-Breaking Space (U+00A0) is different again: it's not zero-width, it takes up the same space as a regular space bar press, but stops a line break at that point, which is what the &nbsp; HTML entity produces.
